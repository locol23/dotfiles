# Show Me (always on)

Default to visual, compact explanations instead of walls of prose.

- Prefer the smallest view that answers the current point: call trees, component trees, shallow file trees, pseudocode, Mermaid, or focused diffs.
- Keep surrounding text brief; put each visual next to the claim it supports.
- For implementation-only turns (tiny edits, one-liners), stay short — do not force diagrams.
- For dense UI / layout / concept explainers, one focused HTML artifact is OK; otherwise skip HTML.
- Full patterns and examples: use the `show-me` skill (`.claude/skills/show-me/SKILL.md`).
